Generative AI Engineering: Useful RAG, Assistants and Agent Workflows

By Abaid Ullah · Full Stack AI Software Engineer

Start with the knowledge task

For a new generative AI project, I would ask what information users need, where that information lives and how they judge a useful answer. A support assistant, document research tool and multi-step automation have different success criteria. The first design task is to define representative requests, including cases the system should decline or send for human review.

The AutoBot is my documented full-stack AI systems work on an assistant combining vector search and knowledge graphs. Study Mind adds document-based reasoning for learners. These projects connect my retrieval and application experience to two different business contexts rather than treating every assistant as the same product.

Evaluate retrieval before decorating the answer

My toolkit includes RAG, GraphRAG, vector databases and orchestration frameworks. For a proposed retrieval system, I would inspect whether the right source material is available and retrieved for representative questions before adjusting response style. I would also include outdated, ambiguous and unsupported questions in the evaluation set.

A useful review separates retrieval problems from response problems. If a relevant document is missing, a polished answer does not solve the underlying issue. I would compare candidate approaches against the client’s examples and retain enough trace information to investigate why an answer was produced. This is my evaluation approach, not a claim about a specific deployment configuration.

Give agent workflows explicit limits

Planet AI represents my work on multi-agent business workflow automation. For a similar product, I would define each tool’s purpose, allowed inputs, completion state and failure behavior. Actions that change external records or communicate with customers should have clearly agreed review rules and an audit trail appropriate to the workflow.

Twin Companion, where my role covered frontend and AI integration, focuses on conversational memory and adaptive responses. It illustrates a different engineering concern: deciding which context should carry forward. For a new assistant, I would align that behavior with user expectations and the application’s retention and access requirements.

Balance answer quality, latency and operating cost

My proposed scorecard would track grounded answers on a reviewed question set, unsupported statements, escalation rates, latency and cost per completed task. For an agent, I would also track whether the intended workflow finishes and whether failed actions can be recovered. These measures provide a basis for choosing between a simpler implementation and a more involved orchestration.

The business goal is a useful, inspectable workflow. I have not published benchmark scores or financial results for these projects here. Any client-specific success claim would need an agreed evaluation method and measured evidence, particularly when changing prompts, retrieval settings or model choices.
